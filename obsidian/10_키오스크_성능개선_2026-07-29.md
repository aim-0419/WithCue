# 키오스크 성능 개선 — 2026-07-29

## 배경

PC에서는 괜찮은데 Jetson 키오스크에서만 `ChooseExercisePage` → `ExerciseIntroPage` 이동, 그리고 로그인 직후 `MainPage` 진입이 눈에 띄게 느려짐. Jetson은 CPU+GPU 통합 메모리 8GB 환경이고 LFB(연속 여유 블록)가 12MB로 단편화된 상태([[03_GPU_메모리_상태점검]] 참고)라, PC GPU라면 무시할 수준의 GPU 컴포지팅 비용도 여기서는 체감될 정도로 느려짐.

---

## 원인 1 — MainPage 진입 지연

파일: `frontend/src/features/main/components/Main.jsx`

세 가지 장식 효과가 동시에 GPU 레이어를 요구하고 있었다.

| 효과 | 문제 |
|---|---|
| `animate-ping` ×2 | 카드 버튼 주변에 무한 반복되는 링 애니메이션 → 계속 GPU 레이어 유지 |
| `blur-3xl` / `blur-2xl` ×4 | 카드당 2개씩 배경 blur 장식 → 필터 연산마다 별도 GPU 레이어 필요 |
| `framer-motion` (`motion.div`, scale+opacity) | 진입 애니메이션 + 라이브러리 초기화 비용 |

**조치**: 세 가지 모두 제거. 대신 순수 CSS `@keyframes` opacity fade-in(0.35s, 카드 2번째는 0.1s 딜레이)과, 버튼에는 정적 `box-shadow` 이중 링 + active 시 opacity press 효과로 대체. `framer-motion` import 자체를 제거해 번들에서도 코드가 빠짐.

## 원인 2 — ChooseExercisePage → ExerciseIntroPage 이동 지연

### 2-1. `willChange: "opacity"`

파일: `frontend/src/features/exercise/pages/ChooseExercisePage.jsx`

sideOptions 모달에 `willChange: "opacity"`가 걸려 있었음. 원래 의도는 "GPU 레이어 재할당 stall 방지"였지만, LFB가 낮은 Jetson에서는 오히려 레이어를 상시 예약해두는 비용이 더 크게 작용함. 제거.

### 2-2. 인라인 `<style>` 블록

`ChooseExercisePage.jsx`, `ExerciseIntroPage.jsx` 둘 다 JSX 안에 `<style>{...}</style>`로 CSS를 인라인 정의하고 있었음. 컴포넌트가 마운트될 때마다 브라우저가 해당 CSS 문자열을 다시 파싱 → CSSOM 재구성. Jetson ARM CPU에서는 이 재파싱 비용이 무시할 수준이 아님.

**조치**: 각각 `ChooseExercisePage.css`, `ExerciseIntroPage.css`로 분리하고 `import "./*.css"`로 교체. Vite가 번들 시 한 번만 처리하므로 이후 네비게이션엔 재파싱 비용이 없음.

### 2-3. 근본적 해결 — 페이지 이동 자체를 제거

사용자 제안: "IntroPage로 페이지 이동하지 말고 모달로 보여주면 더 빠르지 않을까?"

`ChooseExercisePage.jsx`를 전면 리팩터링:
- 기존: 카드 클릭 → `navigate('/exercise/:id/intro')` → 라우트 전환 → `ExerciseIntroPage` 마운트
- 변경: 카드 클릭 → `setIntroId(exerciseId)` → 같은 페이지 안에서 모달(`cw-introCard`)로 운동 안내 표시 → "운동 시작하기" 클릭 시에만 `navigate('/exercise/:id')`로 실제 이동

`EXERCISE_INTRO` 데이터(이름, steps, tips, cover 등)를 `ExerciseIntroPage.jsx`에서 `ChooseExercisePage.jsx`로 그대로 복사해 모달 컴포넌트로 재사용. 페이지 전환이 없어지므로 라우터 언마운트/마운트 비용, 애니메이션 재생 비용이 모두 사라짐.

> **남은 정리 필요 사항**: `App.jsx`의 `/exercise/:exerciseId/intro` 라우트와 `ExerciseIntroPage.jsx` 파일은 이제 어디서도 navigate하지 않는 고아 상태. 동작에는 지장 없지만 원하면 라우트/파일 삭제 가능.

## 원인 4 — (가장 결정적) `localhost:5173`이 구버전 정적 빌드를 서빙 중이었음

모든 소스 수정 후에도 브라우저에서 변화가 감지되지 않는 문제 발생. 원인 확인 결과:

```
pid 10995: vite preview   ← 5173 포트 점유, dist/ 정적 파일 서빙
pid 11037: vite (dev)     ← 5174로 밀려남
```

`vite preview`는 `npm run build`로 미리 빌드해 둔 `dist/` 폴더를 그대로 서빙하는 프로덕션 미리보기 서버. 이 `dist/index.html`의 최종 수정 시각은 **2026-07-23 14:15** — 즉 그 이후 소스 코드를 아무리 고쳐도 5173에는 절대 반영되지 않는 상태였음.

**조치:**
```bash
cd frontend
npm run build          # dist/ 재생성
npx vite preview --host 0.0.0.0 --port 5173   # 최신 빌드로 재기동
```

빌드 후 `dist/assets/index-B27i9ZIu.js`가 실제로 5173에서 서빙되는지 `curl`로 확인.

> **교훈**: 키오스크가 `vite preview`(정적 프로덕션 서버) 방식으로 운영되고 있다면, 코드 수정 후 반드시 **재빌드 → preview 서버 재기동**을 해야 반영됨. dev 서버(HMR)처럼 저장 즉시 반영되지 않음.
