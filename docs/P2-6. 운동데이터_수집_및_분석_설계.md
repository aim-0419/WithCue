## 1. 데이터 수집 구조 (현재 구현 상태)

### 1.1 영상 저장

| 항목 | 사양 |
|---|---|
| 저장 위치 | `backend/public/recordings/{운동명}/record_{timestamp}.mp4` |
| 해상도 | 640 × 360 |
| 프레임 레이트 | **30FPS** |
| 코덱 | mp4v |
| 저장 방식 | 별도 워커 스레드 (메인 루프 블로킹 없음) |

### 1.2 동반 JSON (features 파일)

영상과 동일한 타임스탬프로 `backend/public/features/{운동명}/record_{timestamp}.json` 저장.  
프레임마다 아래 데이터가 누적된다.

```json
{
  "conn_id": "...",
  "reason": "service_stop",
  "frames": [
    {
      "ts": 1718500000.123,
      "accuracy_pct": 87.5,
      "mp_features": { ... }
    }
  ]
}
```

`mp_features`에 들어오는 값은 운동마다 다르다. 운동별 특징값은 3절 참고.

### 1.3 세션 단위 정의

> **1회 동작 = 1 세션**

- 사람마다/운동마다 1회에 걸리는 시간이 다르기 때문에 시간 기준을 두지 않는다.
- 30FPS로 프레임을 수집하고, 분석은 프레임 수 기준으로 수행한다.
- 세션 경계는 phase 전환으로 감지한다 (2절 참고).

## 2. 운동별 시작·종료 구간 추출

영상과 JSON에는 `phase` 정보가 함께 저장된다.  
각 processor가 매 프레임마다 `raising / peak / lowering / idle / ready / transition` 중 하나를 계산한다.

### 2.1 Phase 기반 구간 추출 원칙

```
... idle → [raising → peak → lowering] → idle ...
            ^                           ^
           시작 프레임                 종료 프레임
```

- **시작 프레임**: `idle`(또는 `ready`)에서 `raising`(또는 `transition`)으로 전환되는 순간
- **종료 프레임**: `lowering`에서 `idle`(또는 `ready`)로 복귀하는 순간, 또는 `rep_finished` 이벤트 발생 시점

### 2.2 운동별 보조 기준

| 운동 | 시작 감지 추가 조건 | 종료 감지 추가 조건 |
|---|---|---|
| Shoulder Front Raise | 팔 올림 각도 > 20° | 팔 올림 각도 < 15°로 복귀 |
| Bird Dog | right_arm 또는 left_leg 올림 각도 > 20° | peak_count 2회 달성 후 idle 복귀 |
| Straight Leg Raise | hip_flexion > 10° | hip_flexion < 8°로 복귀 |
| Neck Rotation | neck 회전각 > 10° | neck 회전각 < 8°로 복귀 |

> Bird Dog은 1회 동작이 좌우 교차 2회 peak로 구성된다 (right_arm+left_leg → left_arm+right_leg).
> 시작은 첫 움직임 감지 시점이고, 종료는 두 번째 peak 완료 후 idle 복귀 시점이다.

> 각도 임계값은 실측 데이터 수집 후 운동별로 조정 예정.

### 2.3 유효 동작 판정

다음 조건을 모두 만족해야 유효한 1회 동작으로 인정한다.

- 추출된 구간 길이가 **최소 15프레임(0.5초)** 이상
- 구간 내 `accuracy_pct` 평균이 **30% 이상**
- peak 단계가 **최소 1프레임** 이상 존재

## 3. 운동별 특징값 (mp_features)

### 3.1 Bird Dog

```
[trunk, pelvic,
 right_arm, left_leg, left_arm, right_leg,
 right_arm_h_err, left_leg_h_err, left_arm_h_err, right_leg_h_err,
 right_elbow_angle, left_elbow_angle,
 left_knee_angle, right_knee_angle]
```

- `trunk`: 몸통의 수직 기울기 (체간 안정성)
- `pelvic`: 골반 수평 기울기 (체간 안정성)
- `right_arm / left_leg`: 대각선 팔·다리 올림 각도 (주 동작)
- `*_h_err`: 팔·다리의 수평 이탈 오차 (보상동작 지표)
- `elbow_angle / knee_angle`: 관절 굽힘 각도 (자세 품질)

### 3.2 Shoulder Front Raise

```
[arm_raise_angle, shoulder_elevation, elbow_angle, trunk, ...]
```

- `arm_raise_angle`: 팔 전방 올림 각도 (주 ROM 지표)
- `trunk`: 체간 보상 동작 감지

### 3.3 Straight Leg Raise

```
[trunk, pelvic, knee_angle, ankle_height, hip_flexion]
```

- `hip_flexion`: 엉덩이 굽힘 각도 (주 ROM 지표)
- `ankle_height`: 발목 높이 (다리 올림 정도)
- `knee_angle`: 무릎 굽힘 여부 (자세 오류 지표)
- `trunk / pelvic`: 체간·골반 흔들림

### 3.4 Neck Rotation

```
[neck_angle, shoulder_tilt, ...]
```

- `neck_angle`: 좌우 목 회전 각도 (주 ROM 지표)
- `shoulder_tilt`: 어깨 기울기 (보상 동작 지표)

## 4. 동작 진행률 0~100% 정규화

### 4.1 정규화가 필요한 이유

건장한 성인과 노인이 동일 운동을 수행해도 1회에 걸리는 시간이 다르다.  
시간 기준으로 비교하면 의미 없는 차이가 생기므로, **동작의 진행 단계**를 기준으로 정규화한다.

### 4.2 Phase 기반 이분 정규화

단순 선형 정규화(전체 구간 대비 현재 위치)보다 **올라가는 구간과 내려오는 구간을 따로 정규화**하는 방식을 사용한다.  
올라가는 속도와 내려오는 속도가 다를 수 있기 때문이다.

```
[0%] ──────── raising ──────── [50%] ──────── lowering ──────── [100%]
     start_frame          peak_frame                         end_frame
```

```python
# 올라가는 구간 (0~50%)
if phase == "raising":
    progress = (frame_idx - start_frame) / (peak_frame - start_frame) * 50

# 내려오는 구간 (50~100%)
if phase == "lowering":
    progress = 50 + (frame_idx - peak_frame) / (end_frame - peak_frame) * 50
```

### 4.3 정규화 결과물 구조

```json
{
  "session_id": "...",
  "exercise": "bird_dog",
  "start_frame": 12,
  "peak_frame": 38,
  "end_frame": 61,
  "total_frames": 49,
  "normalized": [
    { "progress": 0.0,  "features": [...], "accuracy_pct": 91.2 },
    { "progress": 5.3,  "features": [...], "accuracy_pct": 89.7 },
    ...
    { "progress": 100.0,"features": [...], "accuracy_pct": 85.1 }
  ]
}
```

## 5. 추출 데이터 항목 및 활용 방안

### 5.1 추출 항목 목록

| 항목 | 원천 | 설명 |
|---|---|---|
| ROM (최대 가동범위) | peak 구간의 주 특징값 최댓값 | 운동 수행 능력의 핵심 지표 |
| 좌우 대칭성 | 동일 progress에서 left/right 값 차이 | 편측 약화 또는 보상 패턴 감지 |
| 체간 안정성 | trunk / pelvic 변위 평균·최댓값 | 허리·골반 흔들림 정도 |
| 보상동작 강도 | `*_h_err`, `elbow_angle`, `knee_angle` | 목표 동작 외 불필요한 관절 움직임 |
| 동작 부드러움 | progress당 특징값 변화율 (1차 미분) | 떨림, 끊김, 반동 동작 감지 |
| 정확도 추이 | `accuracy_pct` vs progress 곡선 | 어느 구간에서 자세가 무너지는지 |
| 실제 소요 시간 | `ts[end] - ts[start]` | 운동 능력 변화 추이 (시간 기록) |
| 3D 깊이 변화 | keypoints의 z값 | 전후 방향 보상동작 (depth 카메라 활용) |

### 5.2 활용 방안

#### 환자 개인 추이 모니터링
- 날짜별 ROM 변화 그래프: 재활 치료 효과를 수치로 확인
- 동일 운동의 세션별 accuracy_pct 누적 비교
- 체간 안정성 점수 추이: 코어 근력 회복 정도 추적

#### 사용자 간 비교 분석
- 정규화된 progress 기준으로 특징값 벡터를 정렬한 뒤 DTW 비교
- 정상 집단의 평균 동작 패턴과 환자 패턴 차이 시각화
- 연령대·성별 분류 후 동일 그룹 내 비교

#### 보상동작 패턴 자동 감지
- 주 동작 각도가 증가하는 구간에서 trunk / pelvic 변위가 함께 커지면 → 체간 보상
- 올라가는 구간에서 elbow / knee가 굽혀지면 → 관절 보상
- 좌우 비대칭이 특정 progress 구간에서 급격히 커지면 → 편측 회피 패턴

#### 참조 동작(Reference) 품질 개선
- 수집된 정상 동작들 중 accuracy_pct 평균이 높고 체간 안정성이 우수한 세션을 선별
- 여러 세션을 DTW로 정렬·평균 → 더 대표성 있는 reference JSON 생성
- 연령·체형별로 분리된 reference 운용 가능

#### 임상 리포트 생성 (향후)
- 세션별 요약: ROM, 대칭성 점수, 체간 안정성 점수, 보상동작 빈도
- 주간/월간 집계: 재활 목표 대비 달성률
- 의료진용 PDF 출력 연동 가능
