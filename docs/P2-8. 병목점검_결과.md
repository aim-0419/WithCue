# P2-4 병목 점검 결과

목표: 1초 이내 피드백, 20 FPS 이상 처리

## 측정 환경

- 디바이스: Jetson Orin Nano (SM87 Ampere, 통합 메모리 7.4GB)
- 모델: yolov8n-pose.pt
- 입력 해상도: 640×360 (STREAM 해상도)
- 카메라 캡처 해상도: 1280×720 (CAMERA 해상도, YOLO에는 미전달)

## 최종 파이프라인 타이밍 (GPU 모드, 30회 평균)

| 단계 | 평균 | P95 | 상태 |
|------|------|-----|------|
| Resize (1280×720 → 640×360) | 1.2ms | 1.2ms | ✅ |
| YOLO 추론 (yolov8n-pose) | 37.4ms | 38.4ms | ✅ |
| JPEG 인코딩 + Base64 | 3.2ms | 3.1ms | ✅ |
| **전체 합산** | **41.8ms** | **42.7ms** | ✅ |

- 추론 FPS: **23.9 FPS** (목표 20 FPS ✅)
- 1회 루프: 41.8ms → 1초 피드백 ✅

## 병목 원인 및 해결

### 초기 상태 (GPU OOM → CPU 폴백)
- 시스템 전체 GPU 사용량 ~6.7GB, 여유 ~913MB
- cuBLAS 초기화에 >1GB 필요 → GPU 추론 불가, CPU 폴백 실행
- CPU 추론 평균: **~900ms → 약 1.1 FPS** (목표 미달)

### 조치 1: 경쟁 프로세스 종료
- uvicorn :8018 (PID 12101) 종료 → GPU 여유 913MB → 1434MB 확보
- Chromium kiosk 모드라 GPU 프로세스는 자동 재시작됨

### 조치 2: cuDNN 비활성화 (핵심 수정)
- pip 설치 PyTorch 2.3.0이 SM87(Orin) 전용 cuDNN 알고리즘 미지원
- `CUDNN_STATUS_EXECUTION_FAILED` → `GET was unable to find an engine` 오류 발생
- `torch.backends.cudnn.enabled = False` 설정 → CUDA implicit GEMM 폴백으로 전환
- GPU 추론 정상 작동, **37.4ms** 달성

수정 위치: `backend/app/services/ai_service.py` `YOLODetector.__init__()` 내 GPU 이동 직전

```python
# Jetson Orin(SM87) pip PyTorch의 cuDNN은 SM87 전용 알고리즘 미지원.
# 비활성화하면 CUDA implicit GEMM 폴백으로 전환되어 정상 작동함.
torch.backends.cudnn.enabled = False
```

## GPU 메모리 사용 현황

| 시점 | GPU 여유 |
|------|----------|
| 초기 상태 | ~913MB |
| 8018 서버 종료 후 | ~1434MB |
| yolov8n-pose 로드 후 | ~1237MB |

## 향후 개선 여지

| 방법 | 예상 성능 | 조건 |
|------|-----------|------|
| NVIDIA Jetson PyTorch 전용 빌드 | cuDNN 정상 지원, 더 빠를 수 있음 | JetPack SDK 재설치 필요 |
| TensorRT `.engine` 변환 | 5~15ms 이하 (3~7× 가속) | `trtexec` 또는 `ultralytics export` 활용 |

현재 23.9 FPS로 목표 달성 상태이므로 TensorRT 전환은 선택적 최적화로 분류.
